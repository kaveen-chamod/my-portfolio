PORTFOLIO CODE AUDIT — BUG LIST
Read-only audit findings

1. Hero — Avatar image is hidden or missing in production
Severity: Medium
Category: UI-UX
Location: src/components/Hero.jsx, approx. lines 137–146
Observed behavior: The hero photo can 404 in a production build, and the fallback graphic is layered over the image even when the image loads.
Root cause: The image uses the literal source-tree URL "/src/assets/hero-avatar.png" instead of a Vite-managed asset import. The opaque, absolutely positioned fallback is always rendered after the image.
Recommended fix: Import the image from ../assets/hero-avatar.png and render the fallback only when image loading fails. For example:

  import heroAvatar from '../assets/hero-avatar.png';
  const [avatarFailed, setAvatarFailed] = useState(false);

  {avatarFailed ? (
    <AvatarFallback />
  ) : (
    <img
      src={heroAvatar}
      alt="Kaveen Chamod"
      className="h-full w-full object-cover"
      onError={() => setAvatarFailed(true)}
    />
  )}

Add useState to the React import and replace AvatarFallback with the existing fallback markup.

4. Coursework — Filter tabs can overflow on very narrow phones
Severity: Medium
Category: Mobile Responsiveness
Location: src/components/Coursework.jsx, approx. lines 64–80
Observed behavior: The four status tabs can exceed the available width around 320px viewports; global horizontal overflow hiding can then clip them.
Root cause: The tab group is a single non-wrapping inline-flex row with horizontal padding on every button.
Recommended fix: Use a two-column layout on small screens and a row at larger widths:

  <div className="grid w-full max-w-md grid-cols-2 gap-1.5 sm:flex sm:w-auto sm:max-w-none">

Also add min-h-11 to each button to preserve an adequate touch height.

7. Navbar — Active section indicator uses ancestor-relative offsets
Severity: Medium
Category: Logic Bug
Location: src/components/Navbar.jsx, approx. lines 20–34
Observed behavior: The active navigation pill can select the wrong section or stop updating while scrolling through sections nested inside positioned wrappers.
Root cause: offsetTop is relative to an offsetParent, while scrollPosition is relative to the document.
Recommended fix: Compare document-relative positions:

  const rect = el.getBoundingClientRect();
  const top = rect.top + window.scrollY;
  const height = rect.height;

  if (scrollPosition >= top && scrollPosition < top + height) {
    setActiveSection(section);
    break;
  }

Observed behavior: Navigating to a section hash can position its heading underneath the fixed navbar.

9. BackgroundGlobe — Animation frame and scene resources are not fully cleaned up
Severity: High
Category: Performance
Location: src/components/BackgroundGlobe.jsx, approx. lines 265–266 and 332–338
Observed behavior: The animation loop can keep rendering after unmount. This can be particularly apparent during React Strict Mode's development effect cleanup/remount and can waste CPU/GPU resources.
Root cause: requestAnimationFrame's ID is not retained or cancelled. Cleanup removes listeners and disposes the renderer, but does not explicitly dispose scene geometries and materials.
Recommended fix: Retain the frame ID, cancel it during cleanup, and dispose scene resources before disposing the renderer. Example:

  let animationFrameId;
  const animate = () => {
    animationFrameId = requestAnimationFrame(animate);
    // update scene and render
  };

  return () => {
    cancelAnimationFrame(animationFrameId);
    window.removeEventListener('scroll', handleScroll);
    window.removeEventListener('resize', handleResize);

    scene.traverse((object) => {
      object.geometry?.dispose();
      const materials = Array.isArray(object.material)
        ? object.material
        : object.material ? [object.material] : [];
      materials.forEach((material) => material.dispose());
    });

    renderer.dispose();
    if (container.contains(renderer.domElement)) {
      container.removeChild(renderer.domElement);
    }
  };

10. BackgroundGlobe — No graceful path for WebGL context loss
Severity: Low
Category: Performance
Location: src/components/BackgroundGlobe.jsx, renderer setup and cleanup (approx. lines 10–20 and 332–339)
Observed behavior: If the browser cannot restore the WebGL context, the decorative globe can remain blank with no explicit fallback or recovery path.
Root cause: No webglcontextlost or webglcontextrestored handling is registered on the renderer canvas.
Recommended fix: Listen for context loss, stop the animation, and keep the rest of the page usable with a static/CSS fallback. Remove event listeners during cleanup. Resume or rebuild only after verifying renderer and scene resources are valid. Example:

  const canvas = renderer.domElement;
  const handleContextLost = (event) => {
    event.preventDefault();
    cancelAnimationFrame(animationFrameId);
    canvas.hidden = true;
  };
  canvas.addEventListener('webglcontextlost', handleContextLost);

11. BackgroundGlobe — Globe renders continuously when animation may be unnecessary
Severity: Medium
Category: Performance
Location: src/components/BackgroundGlobe.jsx, approx. lines 265–329
Observed behavior: The animated background continues to consume rendering time while the user reads other sections, including on mobile devices.
Root cause: The render loop runs continuously regardless of viewport visibility or the user's reduced-motion preference.
Recommended fix: Pause animation when the page is hidden or the globe is offscreen, and honor prefers-reduced-motion. Keep the passive scroll listener: it only stores a value, so it is not itself a significant throttling problem.

14. Projects — Detail modal lacks dialog keyboard and focus behavior
Severity: Medium
Category: UI-UX
Location: src/components/Projects.jsx, approx. lines 144–234
Observed behavior: The modal can be dismissed with its close button or backdrop, but Escape handling, focus containment/restoration, dialog semantics, and background scroll handling are absent.
Root cause: The modal is rendered as ordinary div elements and does not establish an accessible modal interaction.
Recommended fix: Prefer an accessible dialog primitive. At minimum, add role="dialog", aria-modal="true", aria-labelledby pointing to the title, and an accessible label on the close button. Also implement Escape-to-close, focus trapping/restoration, and scroll locking with cleanup; semantics alone do not provide those behaviors.

15. Footer — Contact form reports success without sending a message
Severity: High
Category: Logic Bug
Location: src/components/Footer.jsx, approx. lines 16–23 and 92–140
Observed behavior: Submitting valid fields displays "Your message has been received," but the form sends no request or email. The visitor receives false confirmation and the message is lost.
Root cause: handleSubmit only prevents the default event and updates local state.
Recommended fix: Connect the form to a real API/provider and show success only after a successful response. Add visible loading and error states, and do not show success after a failed request. Example:

  const handleSubmit = async (event) => {
    event.preventDefault();
    const response = await fetch('/api/contact', {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify(formState),
    });
    if (!response.ok) {
      throw new Error('Message could not be sent');
    }
    setFormSent(true);
  };

16. Footer — Clipboard failure still reports "Copied!"
Severity: Medium
Category: Logic Bug
Location: src/components/Footer.jsx, approx. lines 10–13
Observed behavior: The UI reports success immediately even if clipboard access is unavailable or writeText rejects.
Root cause: The clipboard Promise is not awaited or checked.
Recommended fix: Await navigator.clipboard.writeText, display success only after it resolves, and render a visible error/fallback when unavailable. Example:

  const handleCopyEmail = async () => {
    try {
      await navigator.clipboard.writeText(personalInfo.email);
      setCopied(true);
      setTimeout(() => setCopied(false), 3000);
    } catch (error) {
      setCopyError('Could not copy email. Please copy it manually.');
    }
  };
